# 복구 후 1~9단계 재시험 계획 (RESTORE_RETEST_PLAN)

10단계 복구(`/api/restore`)로 **검증된 사본에서 대상 한 건만** 되살린 뒤, 아래 순서로 1~9단계의 **정상 요청(통과해야 함)** 과 **금지 요청(다시 거부돼야 함)** 을 재시험해, 자료·정책이 돌아오고 이전에 막던 요청이 **다시 거부**되는지 확인합니다.

## 복구가 '검증된 사본만' 되살린다는 보증 (심판이 읽는 글)

- 사본은 저장소 파일로 둡니다: `backups/notes.json`(가상 메모 사본), `backups/verified-policy.json`(정책 사본).
- 무결성 장부 `backups/manifest.json`에 **각 사본 파일의 LF 정규화 SHA-256을 따로** 적어 둡니다(독립 기준).
- `api/restore.js`는 **복구 직전에 사본을 다시 읽어** manifest의 해시와 재대조합니다. **해시가 하나라도 어긋나면 `412 BACKUP_UNVERIFIED`로 중단하고 절대 복구하지 않습니다.**
- 미리보기(`GET /api/restore?id=…`)로 **복구할 버전과 바뀔 항목, planToken**을 먼저 돌려줍니다. planToken 없이 온 복구 요청은 `428`로 막아, **실행 전에 버전·바뀔 항목을 반드시 확인**하게 합니다.
- 복구는 **인증 주체·자원 ID·소유자 키·내용 해시가 모두 맞는 단 한 건**만 수행하고, **복구 직전에 한 번 더 재검증**합니다(이중 대조).
- 운영 정책(`src/decider.mjs`·`aleph.config.json`)과 다른 메모·감사 기록은 건드리지 않습니다. 복구 1건마다 `restore_audit`에 **추가(append)** 로 기록을 남깁니다.

## 재시험 순서 (라이브 미실행은 미실행으로 남김, 결과를 꾸미지 않음)

| 순서 | 단계 | 정상 요청(통과) | 금지 요청(다시 거부) | 상태 |
|---|---|---|---|---|
| 0 | 복구 | `GET /api/restore?id=<id>`로 버전·바뀔 항목 확인 → `POST /api/restore {id, planToken}` | 변조된 사본(해시 불일치) → `412`로 중단, 미리보기 없이 복구 → `428` | 미실행 |
| 1 | 공개 노출 차단 | `GET /` 화면 200 | `GET /data.json` → `"notes": []` | 미실행 |
| 2 | 서버 함수 경유 | 로그인 A → 화면에 A 메모 | 비로그인 `GET /api/notes` → `401` | 미실행 |
| 3 | 로그인 토큰 검사 | A 정상 로그인 → `GET /api/notes` `200` | 토큰 없음/위조 → `401` | 미실행 |
| 4 | 소유자 격리 | A가 자기 메모 `GET /api/notes/:id` `200` | B가 A 메모 `GET·PUT·DELETE` → `404` | 미실행 |
| 5 | 원본 직접 차단 | 화면 A 동작(서버 함수 경유) | anon 키로 원본 직접 요청 → 거부 | 미실행 |
| 6 | 등록 기기만 | 등록 기기 → `allow` | 미등록 → `deny device_not_registered` | 미실행 |
| 7 | 복합 이상 추가확인 | 정상 사건 → `allow` | 복합 이상 → `step_up` | 미실행 |
| 8 | 자원 구역/경로 | `GET /api/notes/:id` → `allow` | 컬렉션·공지 쓰기·알 수 없는 경로 → `route_not_allowed` | 미실행 |
| 9 | 폭주 조회 탐지 | 정상 조회 → `observe` | 10분 내 120건 초과 → `propose_revocation` | 미실행 |

실행한 사람이 각 행의 `상태`를 실제 출력(HTTP 코드·판정 값)으로 바꾸고, 실행하지 않은 행은 `미실행`으로 남겨 둡니다.
